## 1. The question, and the wow

The whale paper's evidence that its chunks are "language-like" rests on two baselines,
shuffled song and rotated cut points. Our calibration 1 showed that song generated by
first-order syllable-transition rules **with no words** passes both of them in 20 of 20
replicates. So the real question is the one PREREG.md asked: does real humpback song beat
**null models that keep its own transition rules**? Those are pooled first- and
second-order Markov chains fitted to each year.

* If whale song's Zipf and brevity fits are matched by a first-order chain fitted to each
  year's sound-element transitions, the "language-like" laws in whale song are a property of
  element-to-element transitions, and not evidence of word-like units.
* If they beat even the second-order chain, the evidence for word-like units becomes
  much stronger than the paper itself could show. That would be a result whale and
  language researchers would want to know.

Either way it is the first test of this Science result against a Markov null (PRIOR-ART.md).

## 2. Reading the data (the format is not yet known)

Data S2 ("Song strings") is read by `whale_read.py`. It tries three layouts: one row per
recording, one row per element with header names, and one column per recording. It
accepts a layout only if it passes a **gate built from Table S1 of the paper**:

| year | 2010 | 2011 | 2012 | 2013 | 2014 | 2015 | 2016 | 2017 |
|---|---|---|---|---|---|---|---|---|
| recordings (exact) | 4 | 6 | 6 | 6 | 7 | 12 | 7 | 7 |
| sound elements (within 2%) | 1,053 | 2,028 | 3,351 | 2,664 | 5,765 | 13,251 | 8,469 | 9,179 |

If no layout passes, or two pass with different contents, **no statistic is computed**. The
reading step is then fixed in a separate, published amendment that changes only the reading
(format), and the gate and everything below stay as they are. Only files inside the Data S1-S3
archive are read.

## 3. Pipeline, statistics and nulls

As in PREREG.md for the whale data: one "recording" = one year, with TPs pooled within the
year. One "bout" = one recording's element sequence, so no transition crosses a recording
boundary (the paper: "retaining boundaries between recordings taken at different times").
Forward TPs, the cut rule and the Zipf R^2 come from `zipfseg.py`.

* **Zipf**: mean over the 8 years of the per-year rank-frequency R^2 (paper: 0.93).
* **Brevity, primary `pool`**: one point per chunk type with counts summed over years, OLS
  of log10 count on length (paper Fig. 3A: R^2 0.62). **Alternate `year`**: one point per
  (year, type). Both are graded; when Code S1 is read, the one it uses is the one compared
  with 0.62. The predictions do not change.
* **Runs**: theta 0.5 with B = 1000 per null (primary); theta 0.3 and 0.7 (PREREG.md
  robustness) and 0.25 and 0.75 (the paper's thresholds) with B = 200; the reversed cut rule
  at 0.5 with B = 200. Seed 20261117. There is a time limit of 150 minutes, and the B
  actually reached is recorded.
* **Nulls**: shuffle within each recording (the paper: "shuffling the sound elements within
  each song"), rotation of each recording's cut points (Code S1 `rotate_strings`), pooled
  first- and second-order Markov chains fitted to each year (**primary**), and within-recording
  bigram and trigram resampling. One-sided p = (1 + #null >= real)/(1 + B). z uses the
  population SD.
* **Table S2 check** at theta 0.5: is the paper's most frequent sub-sequence also ours,
  with a count within 10% (or 3), in at least 6 of 8 years?
* **D1** (PREREG.md): leave-one-recording-out log-likelihood, order 2 minus order 1, per year.

## 5. What we will say (rules fixed now)

1. **Labels** (PREREG.md section 5), separately for Zipf and for brevity:
   `BEYOND_SECOND_ORDER` if p(markov2_pooled) < 0.05; `EXPLAINED_BY_SECOND_ORDER` if only
   p(markov1_pooled) < 0.05; else `EXPLAINED_BY_FIRST_ORDER`. For brevity, the real slope must
   be negative to beat a null. Zipf is `REPRODUCTION_FAILED` if S-W fails, and brevity is
   `REPRODUCTION_FAILED` if N4 fails. A label is called robust only if it is the same at
   0.3, 0.5 and 0.7.
2. **No headline unless N1 holds.** If Table S2 is not reproduced, our pipeline differs in
   some detail from the authors'. All numbers are then published as "our implementation on
   their data", and Code S1 is read to find the difference before anything is claimed.
3. **Calibration conditions** (`whale_test.final_reading`):
   * Zipf: a `BEYOND_SECOND_ORDER` label is a headline only if CALIB-2 K5 holds (size). An
     `EXPLAINED_BY_...` label becomes `NOT_DISTINGUISHABLE` if CALIB-2 K6 fails (power,
     CALIB-2 WR2).
   * Brevity: an `EXPLAINED_BY_...` label becomes `NOT_DISTINGUISHABLE` if CALIB-4 Q11 fails
     (power of the second-order null against brevity words). A `BEYOND_SECOND_ORDER` label
     is a headline only if CALIB-4 Q10 holds. Q10 is the size of the first-order null; CALIB-4
     has no second-order size check, so this condition is weaker, and we say so.
   * Until a calibration is graded, the labels it conditions are published as pending.
4. If D1 fails, an `EXPLAINED_BY_SECOND_ORDER` label carries the overfit caveat.
5. Whatever comes out, the result is published with this table, including a failed gate or
   a failed reproduction.

## 6. Known limits, fixed in advance

Log-log R^2 is a weak test of a power law. It is kept because it is the published
statistic. Eight years is a small number of points for the per-year Zipf mean. Second-order
chains fitted to about 1,000-13,000 elements per year can overfit, which is what D1 checks.
Shuffle and rotation here follow the text; if Code S1 does them differently (for example
rotating a whole year at once), that variant is added as a sensitivity run and the primary
stays as registered. "Explained by a Markov chain" says nothing about how whales produce
or perceive song.
